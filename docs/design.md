# 生態系シミュレーションゲーム 設計メモ

## この文書の読み方

これは**確定仕様ではありません**。会話の中で出た設計案を、後から思い出せる形にまとめたものです。

多くの項目、特に数値・パラメータ・技術構成は、実際に動かしてみないと妥当性が判断できません。この文書を根拠に「そう決まっているから」と作り込むと、たぶん間違った方向に固まります。

各項目に確度ラベルを付けました。

| ラベル | 意味 |
|---|---|
| **確定** | 議論して合意済み。変えるならコンセプトから見直す |
| **有力** | 今のところこの方向。実装して感触が悪ければ変える |
| **仮** | 数字や構造は仮置き。ほぼ確実に変わる |
| **未定** | まだ決めていない。判断材料が足りない |

**仮**と**未定**の項目は、実装時に自由に変えてください。特にパラメータの個数、タイルサイズ、時間の秒数、技術スタックの選定は、動かしながら決めるべきものです。

## 1. コンセプト

### 一行で

**生態系を整えるゲームではなく、生態系に賭けるゲーム。** — 確度: 確定

### プレイヤーの立ち位置 — 確度: 確定

プレイヤーは神だが、**個別の事象には触れない**。できるのは確率分布のパラメータを操作することだけ。

「この個体を生かす」はできない。「この地域の降水量の平均を上げる」「この種の変異率の分散を広げる」はできる。結果は世代を進めてみないと分からない。

### 既存作との差別化 — 確度: 有力

既存の生態系ゲーム(Ecosystem、Equilinox、Terra Nil など)はほぼ全て「均衡を作る」ゲームで、絶滅は失敗を意味する。

本作では**絶滅がゲームの燃料**。頂点捕食者が滅ぶとニッチが空き、そこに次の爆発が起きる。プレイヤーは安定を守る庭師ではなく、暴落と爆発に賭ける側。

### スコア — 確度: 有力

**食物連鎖のピラミッドを何段積めたか。**

段が上がるほど下層の生産力が必要になり、基盤が揺らぐと上から連鎖崩壊する。ジェンガと同じ構造で、「6段目を狙うか5段で確定させるか」の判断がギャンブル性を勝利条件に埋め込む。

### 1周の長さ — 確度: 仮

30分〜1時間のローグライト。

### メタ進行 — 確度: 有力

**持ち越すのは知識だけ。** 神の力は強くならない。

初回は世界の法則がほぼ真っ暗でオッズすら見えない。周回して現象を観測するたびに図鑑が埋まり、次周ではオッズが見えるようになる。強くなるのはプレイヤーの目であって、神の力ではない。

## 2. 確率とギャンブル性

### 設計の核 — 確度: 確定

確率を入れただけでは運ゲーになる。ギャンブルが面白いのは以下の3つが揃うから。

1. オッズが事前に見える
2. 賭け金を自分で決められる
3. 降りるタイミングを自分で選べる

この3つを満たさない乱数は入れない。

### 介入の種類 — 確度: 有力(内訳は仮)

因果ループ図の**矢印そのもの**が介入対象。ノードではなくエッジをいじる。矢印1本につき「係数・遅延・分散」の3つのパラメータがある。

操作の種類として想定しているもの:

- **平均をずらす** — 安い。効果は地味だが確実
- **分散を広げる/狭める** — 主役。変異率を上げれば大化けも全滅もする
- **相関をつなぐ/切る** — 上級者向け
- **裾を切る** — 最悪ケースだけ潰す保険。高コスト

主役を分散操作にしたいのは、「期待値を上げるより分散を広げてから当たりを拾うほうが強い局面がある」という非自明さを出すため。

### 賭け金の決め方 — 確度: 仮

抽象的な介入ポイント通貨を置くのではなく、**介入操作そのものに実時間がかかる**案が有力。長押しし続けると賭け金が上がる。エポック内でどこに何秒注ぐかが賭け金の決定になる。

これが成立すると資源管理が「時間」に一本化されてルールが劇的にシンプルになる。ただし操作感が悪い可能性があるので要検証。

### 相関リスク — 確度: 有力

複数の種に分散して賭けたつもりが、裏で同じ気候変数にぶら下がっていて共倒れする。図の上では別々の矢印なのに結合している。この隠れた相関を見抜けるかが実力になる。

### 閾値による不連続 — 確度: 有力

矢印の係数を毎エポック揺らすだけではノイズにしかならない。**閾値**を仕込む。

分解者が一定量を下回ると養分の矢印が切れる、といった不連続点。普段は滑らかに振動しているのに、ある一線を越えると系の構造そのものが変わる。崩壊が不運ではなく**判断の失敗**として体験される。

### 破局イベント — 確度: 仮

氷期・隕石・疫病などの判定。確率は事前に見える(「次のエポックで氷期 12%」)。備えて成長を止めるか、無視して積みに行くかの判断。

耐えた側にとっては、ニッチが空くので大チャンスになる。

## 3. 時間設計とプレイループ

### エポック長 — 確度: 有力(秒数は仮)

**10秒**。リアルタイム進行。

3分案から短縮した。放っておいても世代が進むことが重要で、「指示しない限り何も変わらない」状態にはしない。プレイヤーは常に「間に合っていない」状態に置かれる。

### 二層構造 — 確度: 有力

エポック内でも世界は動き続ける。

- **ティック**(0.5秒程度、仮) — 動物が動き、草が増減する
- **エポック**(10秒) — 賭けの精算、気候の抽選

### 1エポックの流れ — 確度: 有力

観測 → 介入 → 解決 → 記録 の4フェーズが循環する。ただしターン制ではなくリアルタイムなので、フェーズは論理的な区分であって時間的に分離してはいない。

### 介入の遅延 — 確度: 有力

ダイヤルを回した瞬間には何も起きず、しばらく経ってから結果が現れる。「さっき打った賭けの結果を待ちながら次の観測をしている」状態が常時流れる。

### ポーズ — 確度: 仮

ポーズ中は**観察のみ可能・介入不可**。

### 倍速 — 確度: 有力

倍速中は情報が流れて見逃しが発生し、何が起きたかは事後ログでしか分からない。速度選択自体がリスク管理の一部になる。安全な時期は飛ばし、雲行きが怪しくなったら落とす。

### 早期切り上げ — 確度: 仮

エポックを途中で切り上げると、放棄した秒数がボーナスに変換される。毎エポック「時間を使うか、換金するか」の判断が生まれる。

## 4. 因果ループモデル

### 基本方針 — 確度: 確定

**因果ループ図をそのままゲームエンジンにする。** ストックとフロー、フローに乗る係数・遅延・分散。

### ループは独立したモジュールとして書く — 確度: 有力

それぞれのループを独立に実装し、**接続点だけをインターフェースにする**。気候モジュールは生命の存在を知らず、ただ降水量を出力する。生命モジュールは水の出どころを知らず、入力として受け取る。

こうすると後からループを足せる。地質ループ(侵食と堆積)、火のループ、伝染病のループなど。

### 生命ループ — 確度: 有力

```
草 --(餌 +)--> 草食獣 --(餌 +, 遅延)--> 捕食者
 ^                ^                        |
 |                |                        |
 |            (捕食 -)  <------------------+
 |                |
 |            (採食 -)
 |                v
 +--(養分 +, 遅延)-- 分解者 <--(死骸 +)-- 捕食者
                        ^
                        +--(排泄 +)-- 草食獣
```

重要なのは**正のループと負のループが混在している**こと。

- 外周(草→草食獣→捕食者→分解者→草)は栄養が一周する正のループ。遅延が2箇所
- 草⇄草食獣、草食獣⇄捕食者は即応する負のフィードバック

遅延のある正のループと即応する負のループが同居すると、系は必ず振動する。減衰して落ち着くか発散して崩壊するかは係数次第。

### 気候ループ — 確度: 有力

```
大気の水分 --> 降水 --> 地表の水 --> 蒸発 --> 大気の水分
```

生命ループとは独立に回る。生命が全滅しても回り続けるので、**世界が続くから再挑戦できる**。

### 気温 — 確度: 有力

矢印ではなく、**複数の矢印に同時に効く係数**。

気温が上がると蒸発が速まり、同時に降水も増える。一見バランスするが、蒸発は即座で降水は遅れる。だから温暖化局面では一時的に地表の水だけが減る。単一の変数が遅延の異なる2つの矢印を動かすことで、系全体が脱水する。

### 気候ループと生命ループの接続点 — 確度: 有力

接続は**2箇所だけ**。

1. **供給** — 降水が草に水を与える
2. **保水** — 分解者が土の保水力を上げる

保水の矢印が効く。分解者が減ると土が水を保てなくなり、同じ雨量でも草が育たない。**気候は変わっていないのに干ばつが起きる**。プレイヤーは空を見上げるが、原因は足元にあって、しかも見えない。

## 5. 表示とマップの符号化

### 3層の優先順位 — 確度: 確定

1タイルには1つの記号しか描かない。重ね表示はしない。

1. **動物** — 最優先。いれば必ず見える
2. **植物** — 動物がいなければ文字として見える
3. **背景** — 地形と量。常時見える
4. **分解者** — 表層には一切出ない。専用レイヤーでのみ見える

下の層ほど見えにくく、しかし崩れるときは下から崩れる。**可視性とピラミッドが逆転している。**

副作用として、動物がいるタイルの植生の高さは直接見えない。群れが移動して初めて、そこがどれだけ食い荒らされたかが露出する。

### 2軸の分離 — 確度: 確定

- **背景色 = 量**(バイオマス)
- **文字 = 構造**(植生の高さ、隠れ場所の有無)

この2つは独立に変化する。

- 密生した低草 = 餌は豊富だが隠れられない。草食獣にとっては罠
- まばらな藪 = 餌は乏しいが安全

自己調整ループが自然に回る。草食獣が食べ過ぎると量が減り、同時に高さも失われ、隠れ場所がなくなって捕食される。

### 記号 — 確度: 有力(具体的な文字は仮)

陸上の構造:

| 記号 | 意味 |
|---|---|
| (なし) | 裸地 |
| `.` | 低草。見晴らしがよく隠れられない |
| `w` | 中草。小動物なら隠れられる |
| `W` | 藪。大型動物も潜める |

水中の構造(深さが隠れ場所を兼ねる):

| 記号 | 意味 |
|---|---|
| (なし) | 開けた浅瀬。最も危険 |
| `,` | 藻マット |
| `v` | 海藻 |
| `Y` | ケルプ林、深み |

木は一旦なし。高さの軸を3段に統一したので、後から「藪より高いもの」として4段目に足せる。

### 動物の記号 — 確度: 有力

**形が食性を表す。**

- ● 丸 = 植物食
- ▲ 三角 = 肉食
- 大きさ = 体格

魚も陸の動物と同じ記号を使う。水か陸かは背景で分かる。進化で肉食化したら丸が三角に変わる。

### 裸地と土の質 — 確度: 未定

背景色の最も薄い状態が自動的に裸地になるので、専用記号は不要。

ただし裸地には「土の質」という別の軸がある。痩せた土と、火事の直後で栄養が残っている土では次に生えるものが違う。**これは現状の3チャンネルでは表現できていない。**

案として、土の質は分解者レイヤーが担う。表層では見えず、レイヤーを切り替えると初めて「この裸地は肥沃だ」と分かる。

### 進化した新種の記号 — 確度: 仮

親の文字を継承する。大きな変異が起きたときだけ新しい文字を割り当てる。文字を見るだけで系統が分かり、キャストが増えても覚え直さなくていい。

### レイヤー切り替えのコスト — 確度: 仮

分解者レイヤーは切り替えて見に行くしかない。切り替え中は動物の動きを見逃す。**表層を見るか土を見るか**のトレードオフ。

大半の時間は動物を眺めてしまうが、本当に必要な情報は土の中にある。この誘惑の構造がゲームの難しさになる。

## 6. 種のデータ構造

### 設計原則 — 確度: 有力

**神のダイヤルで動かせないパラメータは持たない。** 動かせないならそれは定数であってパラメータではない。

パラメータが増えるほど、神が回すダイヤルとの対応が見えなくなる。

### パラメータ最小セット — 確度: 仮

**この一覧は特に流動的です。実装しながら足し引きしてください。**

| パラメータ | 役割 |
|---|---|
| 体格 | 捕食関係と必要餌量を両方決める中心パラメータ |
| 食性 | 植物食 / 肉食 / 腐食、および水中か陸か |
| 生息層 | 水底・水中・水面・地表・樹上。隠れ場所の要求もここに紐づく |
| 寿命 | 世代の回転速度。短いほど進化が速いが絶滅もしやすい |
| 繁殖 | 一度に産む数と、繁殖に必要な条件 |
| 代謝 | 消費する量と、排泄として分解者に返す量 |
| 耐性 | 気温と水分の許容幅 |

### 捕食関係は導出する — 確度: 有力

種ごとに「誰を食べるか」を持たせると組み合わせ爆発する。**形質ベースで判定する。**

おおよそ「自分より一定以上小さくて、同じ層にいて、防御を突破できる」なら捕食可能。進化で新種が生まれても捕食関係が自動的に決まる。

上下関係を独立パラメータにはせず、体格と食性から導出する。

### 少産少死と多産多死 — 確度: 有力

賭けとして最も効く軸。

- **多産多死** — 分散が大きい。急に増えるが急に消える
- **少産少死** — 分散が小さい。安定だが一度減ると戻らない

**ピラミッドの上に行くほど少産少死になる**ので、高い段を積むほど自動的に脆くなる。ジェンガの構造そのもの。

## 7. 海と陸の接続

### 方針 — 確度: 有力

海と陸を独立させると不自然になる。**境界の生物が両方の系から栄養を運ぶ。**

システム的には「水の分解者プールと陸の分解者プールを繋ぐ矢印を持つ種」と定義できる。

### 繋ぎ役の3タイプ — 確度: 仮

| タイプ | 役割 |
|---|---|
| 両生的な捕食者 | 水から獲って陸で排泄する。海の栄養を陸へ |
| 遡上する魚 | 海で育ち川で死ぬ。死骸が内陸の分解者を養う。一方向の巨大な栄養ポンプ |
| 飛ぶ虫 | 水中で幼生、陸で成虫。量は小さいが常時流れる |

### 副次効果 — 確度: 有力

繋ぎ役は**隠れた相関を作る存在**でもある。いるうちは分散が効いているように見えて実は連動している。滅ぶと初めて独立する。「滅んで安全になる種」という珍しい役回り。

## 8. 技術構成

**この章は全体的に確度が低いです。** 動かしてみて問題が出たら躊躇なく変えてください。

### 配信形態 — 確度: 有力

- ブラウザアプリ
- サーバー機能なし
- GitHub Pages で配信
- ビルド成果物は静的ファイルのみ

GitHub Pages はサブディレクトリ配信になるので、アセットのパスは相対にしておく。

### タイルサイズと盤面 — 確度: 仮

1280×720 の描画領域を想定した場合:

| タイルサイズ | 盤面 | タイル数 | 備考 |
|---|---|---|---|
| 8px | 160×90 | 14,400 | 文字は入らない。色と点のみ |
| 12px | 106×60 | 6,400 | 小さめの等幅文字がぎりぎり読める |
| 16px | 80×45 | 3,600 | 文字も動物記号も余裕 |

12px あたりが候補。あるいは 8px を基本にしてズームで 16px に寄れるのが理想。引きで色を読み、寄って個体を見る。

### 描画 — 確度: 有力

- **Canvas に直接描く。** タイル1つを DOM 要素にするのは数千個で破綻する
- **部分更新。** Canvas は描いたものが残るので、変わったタイルの矩形だけ塗り直せばよい。差分計算の仕組みは不要で、「どのタイルが変わったか」をリストに溜めておくだけ
- **文字はスプライト化。** 起動時に全記号(色違い含む)をオフスクリーン Canvas に焼いておき、描画時は矩形コピーのみ
- 文字はタイル境界内に収める。はみ出していると隣を塗り直したときに欠ける

ちらつきについては、Canvas は標準でダブルバッファ相当の動作をするので、部分更新にすれば問題は起きないはず。ちらつきの原因はたいてい全消ししてから描き直していること。

### 計算 — 確度: 仮

シミュレーション本体を **Web Worker** に置く。メインスレッドでやると描画が引っかかる。Worker で計算して結果の配列だけをメインに渡して Canvas に描く。倍速機能を入れるなら特に効く。

### 保存 — 確度: 仮

- **localStorage** — 設定、図鑑の進捗など小さいもの。上限5MB前後、文字列のみ
- **IndexedDB** — 盤面のスナップショット。数千タイル×十数パラメータを Uint8Array / Float32Array の塊として保存すれば数百KB程度

タイル状態を localStorage に JSON で入れるのは容量的に厳しい。

## 10. 最初に作るもの

**草と草食獣だけの最小プロトタイプ。** 捕食者も気候もなし。

確認したいこと:
