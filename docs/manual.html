1. 全体像

80×45 タイルのトーラス（端がつながった）盤面で、草・草食獣・肉食獣・死骸・土壌養分の5つが相互作用するリアルタイムシミュレーション。プレイヤーの介入（神のダイヤル・賭け）はまだ無く、今は「生態系が放っておくとどう振る舞うか」を観察する段階。

時間

1 tick = 500ms。20 tick = 1 エポック（10秒）。エポックは現状カウンタだけで、何も起きない（将来の賭け精算・気候抽選のフック）。

盤面

80×45 = 3,600 タイル。1タイル 16px。上下左右が折り返してつながる。

初期状態

草はほぼ全面に生えた状態から始まり、草食獣150・肉食獣12がランダム配置。乱数シードは起動時刻（UIからの指定は不可）。

典型的な推移

草食獣が爆発的に増える → 草を食べ尽くす／捕食者が増えすぎる → 崩壊 → 生き残りと土壌から回復、の波。絶滅は普通に起きる。

2. 因果ループ（モデルの本体）

ストック（箱）とフロー（矢印）。機能追加を考えるときは、まず「どの箱を増やすか／どの矢印を足す・変えるか」をこの図の上で言えるようにする。

このループの性質

  • 草は無から生えない。成長は必ず同じタイルの土壌養分を1:1で消費する。養分がゼロなら何も起きない。
  • 養分の入口は4つ：枯死（自タイルへ）・散布（隣8タイルへ）・排泄・死骸の分解。前の2つは動物がいなくても働く（遅い）、後の2つは動物由来（速い）。
  • 遅延は死骸の分解だけ。死んでから養分になるまで10 tick。design.md が想定する「草食獣→捕食者の遅延」はまだ無い（捕食の効果は即時）。
  • 質量は保存されない。散布は元のタイルのbiomassを減らさずに養分を生む。死骸はその個体が何を食べたかに関係なく一定量（0.4）を返す。モデルは定性的な因果の再現を目的にしていて、物質収支は合わせていない。

3. 1 tick の処理順

順番に意味がある。後の段は前の段の結果を見て動く。すべて Worker 内の sim/loop.ts の tick() で実行される。

  1. 草 stepGrass
    1. 全タイルのbiomassをスナップショット（走査順で結果が偏らないように）
    2. biomass > 0 のタイルごとに：自分のbiomassの senescenceRate 分を減らして自タイルの養分に足す（枯死）。さらに spreadRate 分を8等分して隣の養分に足す（散布、元は減らない）
    3. 全タイルで成長：余地 = growthRate × (capacity − biomass)、成長量 = min(余地, 養分)。養分を同量減らす
  2. 草食獣 stepHerbivores（配列順に1体ずつ。前の個体が食べた結果を次の個体が見る）
  3. 肉食獣 stepCarnivores（草食獣が動き終わった後の位置を狙う。この段で食べられた草食獣は段の最後にまとめて除去）
  4. 死骸 stepCarcasses（全死骸が養分を放出し、10 tick 経ったものを消す）
  5. 描画差分の計算 deriveHeightAndColor（見た目の段階が変わったタイルだけを返す）
  6. エポックの判定（20 tickごとにカウンタを進めるだけ）

死骸による通行止めは、各段の開始時点に存在する死骸で判定する。草食獣の段で出た死骸は、同じtickの肉食獣の段では通行止めになる。

4. ライフサイクル仕様

数値は src/sim/params.ts の写し。ここを変えるときは「なぜその値か」を判断の記録（10章）にも残す。

4.1 ピラミッドの原則

上の段ほど「少なく・遅く・長生き」。design.md section 6 の「少産少死」を数値の大小関係で守る。 草の再生 ≥ 草食獣の繁殖 ≥ 肉食獣の繁殖、の順を逆転させない。

個体数の上限2000150上の段ほど小さい
初期個体数15012上の段ほど小さい
繁殖できる空腹度（以下）0.150.05上の段ほど厳しい
繁殖で増える空腹度0.30.7上の段ほど重い
寿命（tick）200（約100秒）600（約300秒）上の段ほど長い
空腹の進み（/tick）0.050.04上の段ほど遅い

4.2 草（タイルごとの状態）

状態意味
biomass 0〜1生えている草の量。背景色と文字の両方を決める
fertility 0〜1土壌養分。成長の唯一の材料。表示されない（design.md の「分解者は表層に出ない」に対応）
パラメータ値意味
growthRate0.03capacity までの残りのうち、1 tick で埋められる割合（ただし養分の範囲内）
capacity1.0biomass の上限
grazePerBite0.15草食獣の1口で減る量
spreadRate0.002自分のbiomassのうち、隣8タイルの養分に分ける割合（元は減らない）
senescenceRate0.0001自分のbiomassのうち、枯れて自タイルの養分に戻る割合（元が減る）
fertilityCap1.0養分の上限

初期値：biomass は10%のタイルが疎（0.15〜0.25）、10%が密（0.75〜0.95）、残りが0.3〜0.8。fertility は biomass の半分。

4.3 草食獣 ●

状態は 空腹度 hunger（0=満腹〜1=餓死）と年齢 ageの2つだけ。この2つは独立していて、どちらか一方で死ぬ。蓄えという概念は無く、空腹度は毎tick必ず上がり、食べた時だけ下がる。

  1. 移動：自タイルと隣8タイルのうち、草が一番多いタイルへ1マス動く（死骸のあるタイルは候補から外す。同じ量のときはわずかな乱数で決まり、その場に留まるより隣へ移りやすい）
  2. 空腹：hunger += 0.05
  3. 採食：そのタイルの草が 0.1 を超えていれば最大 0.15 食べ、hunger −= 0.1 × (食べた量 / 0.15)。食べた量の半分をそのタイルの養分に返す（排泄）
  4. 加齢：age += 1
  5. 死：hunger ≥ 1（餓死）または age > 200（老衰）でその場に死骸を残して消える
  6. 繁殖：生き残り、かつ hunger ≤ 0.15 なら同じタイルに子を1体（子の空腹度 0.5）。親は hunger += 0.3。無性生殖

収支の目安：毎tick食べ続けられれば空腹度は 0.05 ずつ下がる。2 tick に1回しか食べられないと横ばい、それ以下なら餓死に向かう。飢えだけで死ぬまで最短 20 tick（約1エポック）。

4.4 肉食獣 ▲

草食獣と同じ2つの状態（空腹度・年齢）。違いは餌が「草」ではなく「そのタイルにいる草食獣」であること。

  1. 移動：自タイルと隣8タイルのうち、まだ誰にも捕まっていない草食獣が一番多いタイルへ1マス動く（死骸タイルは除外）
  2. 空腹：hunger += 0.04
  3. 捕食：そのタイルに草食獣がいれば1体捕まえて hunger −= 0.3。捕まった草食獣はこのtickの終わりに消え、死骸は残さない（養分は捕食者に移る扱い）。1体の獲物を2体の捕食者が取り合うことは無い
  4. 加齢：age += 1
  5. 死：hunger ≥ 1 または age > 600 でその場に死骸を残して消える
  6. 繁殖：hunger ≤ 0.05 なら子を1体（子の空腹度 0.5）。親は hunger += 0.7

収支の目安：1回の捕食（−0.3）で約7 tick分の空腹を賄う。繁殖するには捕食を何度も重ねて空腹度を 0.05 以下まで下げる必要がある。

項目値仕様

9. 既知の単純化・技術的負債

  • 処理順の偏り：個体は配列順に1体ずつ処理され、前の個体の結果を後の個体が見る。配列の前の方の個体がやや有利。
  • 草食獣は逃げない。捕食者の位置を見ずに草だけを追う。捕食は隣接すれば必ず成功する。
  • 視野は隣1マスだけ。HERBIVORE_PARAMS.visionRadius は定義されているが使われていない。
  • 無性生殖。検討の上、現段階では雌雄を入れないと判断（10章）。
  • 質量非保存（2章）。散布と死骸が、実質的な外部からの養分流入になっている。
  • 長時間の検証手段が無い。回復のような数千tickの挙動は、DEFAULT_TICK_MS を一時的に 20 に書き換えて早送りして確認している。倍速UIか、ヘッドレスで回す検証スクリプトがあると良い。
  • 乱数シードを固定できない。同じ条件の再現・比較ができない。
  • 1回の観察に依存した調整がある。実機確認の多くは1回の試行。シードによって結果が変わりうる。

10. 判断の記録

同じ議論を繰り返さないための記録。新しい順。

判断理由・経緯
肉食獣の繁殖条件を大幅に厳しくし、上限を500→150に最初の設定（捕食1回で −0.5）では捕食者391 対 草食獣9と、捕食者が40倍に増えた。ピラミッドが逆転していた
捕食された個体は死骸を残さない体は捕食者に移る扱い。自然死だけが死骸として分解者に回る（design.md の「死骸 ← 捕食者」の矢印に対応）
死骸のパラメータを種共通の CARCASS_PARAMS に体は種によらず体。種ごとに変える必要が出たら分ける
枯死（senescence）でbiomass自体も減らす「草も死ぬべき、代謝があるべき」。養分を還元するだけだと、満タンの草が無限の泉になっていた
spreadRate 0.05 → 0.002、senescenceRate 0.01 → 0.0001動物に依存しない養分の入口が強すぎて、草食獣が400〜480頭で均衡し絶滅しなくなった。切り分けると主犯は spreadRate。弱めても、全滅後の全面回復は約2500 tickで起きることを確認
枯死による養分還元を追加養分の入口が動物由来だけだと、全滅した瞬間の状態で盤面が凍りつく
無性生殖のまま（雌雄は入れない）design.md の繁殖仕様も「産む数と条件」のみ。雌雄は相手探しや性比の崩壊という大きな仕組みを持ち込むので、現段階では見送り
草の広がりを「成長ポテンシャルへの加算」から「隣への養分の受け渡し」に加算方式は、結局そのタイル自身の養分が無いと効かず、体感できなかった
死骸を見える物体にし、分解中は通行不可に死 → 分解 → 養分 → 草、という因果ループを画面上で見えるようにするため
土壌養分（fertility）を導入草が無条件に回復していたので、食べ尽くしても何もない土地から生え、絶滅しなかった
energy を hunger（空腹度）と age（年齢）に分離energy は餓死判定と繁殖の燃料を兼ねていて、過去の蓄えで長く生き延び・繁殖できてしまった
grazeHungerRelief 0.25 → 0.1たまに1口食べれば繁殖し続けられる抜け穴になっていた
寿命 2000 → 200 tick老衰が実質起きず、多産多死になっていなかった
却下：密集によるペナルティ死「密集しているから死ぬ」は論理の飛躍。増えすぎた結果は餌不足による餓死で表現する
タイル 12px → 16px12pxでは W などの文字が潰れて読めなかった
Web Worker を最初から採用design.md の方針。倍速を入れるときに効く

11. 開発の進め方

このマニュアルをモデルとして扱う。依頼を受けたら、コードより先にこの文書の上で考える。

  1. 位置を決める：2章の因果ループで、どの箱（ストック）を足すのか、どの矢印（フロー）を足す・変えるのかを言葉にする。3章の処理順のどこに入るかも決める。
  2. 影響を洗う：7章の不変条件のどれに影響するか。4.1のピラミッドの順序を崩さないか。10章で過去に却下・決着した案の蒸し返しになっていないか。8章の未実装項目との関係。
  3. 受け入れ基準を先に書く：「何が観察できたら完成か」を、単体テストで確かめられるもの（ミクロ）と、実機で観察するもの（マクロな挙動）に分けて書く。モデルが変わるなら、実装前にマニュアルの変更案をユーザーと合意する。
  4. 実装：6章のモジュール境界を守る。数値は params.ts に置き、理由をコメントに書く。
  5. 検証：npm run typecheck、npm run test、ブラウザで観察。長時間の挙動は早送りで確認する。
  6. マニュアルを更新：同じコミットで、モデル図・処理順・パラメータ表・不変条件の状態・判断の記録を直す。確認していないものを「確認済み」にしない。

受け入れ基準の書き方（テンプレート）

機能: （例）草食獣が捕食者から逃げる
因果ループ上の位置: 肉食獣 → 草食獣 に「回避 −」の矢印を追加。処理順は草食獣の移動
影響する不変条件: INV-09（変わらない）、INV-13（改善を期待）、INV-11（絶滅しにくくなる恐れ）

                    ピーク時の捕食者:草食獣の比が 1:5 より小さい
